# Batch 02: Supabase Storage Foundation

## 1. Scope
Establishing Supabase Storage integration foundation (`public-media` bucket) for media asset management (user avatars, barber photos, service images). Uses Firebase Auth ID tokens for storage request authorization without creating Supabase Auth sessions.

---

## 2. Affected Files

- `[MODIFY]` [supabase.ts](file:///e:/app/urbarber/src/lib/supabase.ts) (Harden Supabase client init, ensure `accessToken` getter retrieves fresh Firebase Auth ID token)
- `[MODIFY]` [storage.service.ts](file:///e:/app/urbarber/src/features/services/storage.service.ts) (Implement storage helper functions for uploading media to `public-media` bucket)
- `[NEW]` [storage.types.ts](file:///e:/app/urbarber/src/features/services/storage.types.ts) (Define types for uploaded media, folder paths, and file response objects)

---

## 3. Acceptance Criteria

1. Supabase client in `src/lib/supabase.ts` initializes cleanly without throwing uncaught errors when valid `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are configured.
2. No Supabase Auth sessions or `supabase.auth` calls are created or invoked.
3. `uploadPublicImage` in `storage.service.ts` accepts an `ImagePickerAsset`, reads arrayBuffer, and uploads to `public-media/{folder}/{filename}` using current user's Firebase UID folder prefix.
4. Function returns public HTTP URL generated by Supabase Storage.
5. Unauthenticated upload attempts throw a clean descriptive error ("Pengguna belum login").

## 6. Rollback Notes

If Supabase Storage integration fails:
1. Revert `src/lib/supabase.ts` and `src/features/services/storage.service.ts` using `git checkout HEAD -- src/lib/supabase.ts src/features/services/storage.service.ts`.
2. Delete `src/features/services/storage.types.ts`.
3. Check network connection and Supabase publishable key settings in `.env.local`.
